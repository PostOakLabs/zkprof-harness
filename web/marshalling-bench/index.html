Marshalling bench

What it costs to cross the JavaScript ↔ WebAssembly boundary, and how much of that cost goes away if you batch across it. One Poseidon compression per crossing, then batched ×8, ×32 and ×128, against a pure-copy baseline that crosses the same bytes doing nothing.

What this measures

Every other row in a zkprof-report is compute. In a browser there is a cost that is not compute, and that no compute profiler can see: the crossing itself. A call into wasm is not free, and a call that performs one small hash pays the whole crossing to move 64 bytes.

The loop being timed lives in JavaScript, not in Rust. A Rust loop never crosses the boundary, so a Rust loop cannot measure it. The wasm side times only the work it does on its own side of the crossing, and the difference is attributed to marshalling.

Deployment context

Read here, on the main thread, before anything is measured. The report carries its own copy of crossOriginIsolated; if the two disagree, the bench is running in a context the report does not describe.
